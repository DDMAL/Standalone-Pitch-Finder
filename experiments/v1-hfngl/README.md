# v1 stave-step CNN: Hufnagel experiments

A per-glyph CNN that regresses one continuous stave step from a crop,
compared against `pitch_finder.py`'s heuristic. Single-note glyphs only
(multi-note neume decomposition is out of scope for v1).

## Layout

| File | Purpose |
|---|---|
| `model.py` | `StepCNN` architecture |
| `data.py` | loads real/pseudo-labeled glyph crops, staff-condition selection |
| `split.py` | shared train/test split (per-page + per-class stratified) |
| `train.py` | trains and saves `checkpoints/stepcnn_{real,real_pseudo}.pt` |
| `evaluate.py` | 4-way comparison against the held-out test set; loads the checkpoints above |
| `staff_originals/` | true pre-correction staff geometry for the 5 hand-fixed pages (see below) |
| `checkpoints/` | trained weights + `meta.json` |

```
python train.py       # writes checkpoints/
python evaluate.py    # reproduces the results below from those checkpoints
```

## Architecture

```
Conv(1,16,3)+ReLU+Pool -> Conv(16,32,3)+ReLU+Pool -> Conv(32,64,3)+ReLU
-> AdaptiveAvgPool2d((8,1)) -> Flatten+Dropout -> Linear(512,64)+ReLU -> Linear(64,1)
```

`AdaptiveAvgPool2d((8,1))` keeps 8 vertical bins into the head instead of
collapsing the whole spatial map to one value per channel. The original
`AdaptiveAvgPool2d(1)` did that and mode-collapsed (exact-match ~25-29%);
this fix alone got it to ~80-89%. ~56k params, no augmentation.

## Data

13 fully hand-annotated Hufnagel pages (2607 stave steps total; 1205
single-note glyphs used here -- 958 train / 247 test). 5 of the 13 needed
staff-line correction via `fix_stafflines.py` before the heuristic was
usable: `CantusMA1537_p22`, `MS025a-01`, `MS025a-02`, `MS025b-01`,
`MS234_p005`. `staff_originals/` holds each one's **true** pre-correction
geometry (git-recovered for `CantusMA1537_p22`, reconstructed from Gen's own
untouched bbox annotations for `MS025a-01`/`MS234_p005`, regenerated by
rerunning `mothra/staff-finding` for `MS025a-02`/`MS025b-01`, which have no
Gen staff boxes at all) -- used only by experiment (2) below.

Test split: per page, 20% held out (stratified by class), with pages under
5 real single-note labels going entirely to train. Guarantees every folio
and every common class shows up in the test set.

## The 4 experiments (same 247-glyph test set)

1. **Heuristic, with human-corrected staff.**
2. **Heuristic, with the true pre-correction staff** (the 5 pages above only).
3. **CNN, trained on real labels only** (958 glyphs).
4. **CNN, trained on real + pseudo labels** (+23 heuristic-guessed glyphs
   from pages with real Gen staff boxes -- pool is nearly exhausted now
   that almost every eligible page has been fully hand-annotated).

## Results

| Experiment | n | exact% | within1% | MAE |
|---|---|---|---|---|
| (1) heuristic, corrected staff | 247 | **87.9%** | 94.7% | 0.190 |
| (2) heuristic, uncorrected staff | 233* | 55.8% | 70.4% | 1.760 |
| (3) CNN, real labels only | 247 | 79.8% | 97.6% | 0.227 |
| (4) CNN, real + pseudo labels | 247 | 81.4% | 97.6% | 0.211 |

\* 14 glyphs had no pixel-anchor coverage under the uncorrected geometry.

Per-page, (1) vs (2) on the 5 corrected pages -- staff correction is worth
far more than anything else tried:

| Page | corrected | uncorrected |
|---|---|---|
| MS025a-01 | 100.0% | 7.1% |
| MS025a-02 | 95.5% | 11.8% |
| CantusMA1537_p22 | 90.6% | 10.3% |
| MS234_p005 | 88.2% | 66.7% |
| MS025b-01 | 82.8% | 57.1% |

## Findings

1. **Manual staff-line correction is the highest-leverage thing tried by
   far** -- dwarfs any architecture or data-volume change.
2. **Heuristic (with good staff) still beats the CNN**, 87.9% vs 79.8%
   exact-match, though the gap has narrowed as real data grew. The CNN's
   `within1` is consistently better (97.6% vs 94.7%): its misses are
   smaller, just more frequent.
3. **Pseudo-labeling gave a small positive bump this run** (79.8% ->
   81.4%) -- the first positive result after several earlier attempts that
   didn't help -- but from only 23 examples, likely too few to trust. The
   pseudo pool is now nearly exhausted (every eligible source page has been
   hand-annotated); growing it further would need new pages, not more
   pseudo mining of existing ones.

## Caveats

- Single-note-only scope: says nothing about multi-note decomposition.
- Most classes other than `punctum`/`virga` have under 10 test examples --
  don't over-read their per-class percentages.
- `MS025a-02`'s page folder was rebuilt mid-project after discovering it had
  been built against the wrong image export (bboxes matched a 1537x2049
  "medium" scan but the folder used a 3075x4098 "large" one) -- every crop
  had been reading the wrong region. All numbers here use the rebuilt
  version; the old one is at `../../MS025a-02_OLD_WRONG_SCALE_backup/`.
